# Supabase Diagnostics Script - Quick Reference

## 📦 What It Does

Generates a **safe, shareable** diagnostics bundle for debugging Supabase issues:
- ✅ No user data
- ✅ No secrets or API keys  
- ✅ No connection strings with passwords
- ✅ Only schema definitions and metadata

## 🚀 Usage

```bash
# Make executable (already done)
chmod +x generate_supabase_diagnostics.sh

# Run the script
./generate_supabase_diagnostics.sh
```

## 📋 What Gets Collected

1. **Supabase CLI version** - For version compatibility checks
2. **Project list** - Available projects in your account
3. **Project status** - Local project link status
4. **Schema dump** - DDL only (no data)
5. **TypeScript types** - Generated database types
6. **Database metadata**:
   - RLS policies
   - Triggers
   - Extensions
   - Foreign keys
   - Grants
   - Indexes
   - Column definitions
7. **Migrations archive** - All your migration files
8. **Environment variables** - Names only (values redacted)

## 📦 Output

Creates `supa_diag_bundle.zip` in your project root containing all diagnostic files.

## 🔒 Security

All sensitive data is automatically redacted:
- Connection strings → `<REDACTED>`
- API keys → `<REDACTED>`
- Passwords → `<REDACTED>`
- User data → Not included (DDL only, no data dump)

## 🛠️ Prerequisites

- Supabase CLI installed (`brew install supabase/tap/supabase`)
- Logged in to Supabase (`supabase login`)
- Project reference detectable (from `.env.local`, `.env`, or supabase status)

## 📤 Sharing

Safe to share with:
- Support teams
- Developers
- Public issue trackers (if schema is not proprietary)

## ⚠️ Troubleshooting

**"Supabase CLI not found"**
```bash
brew install supabase/tap/supabase
```

**"Not logged in to Supabase"**
```bash
supabase login
```

**"Could not detect project reference"**
- Check that `.env.local` or `.env` contains `EXPO_PUBLIC_SUPABASE_URL`
- Or run `supabase link --project-ref YOUR_PROJECT_REF` first

**"Connection failed"**
- Script will still generate bundle with available information
- Some metadata may be missing but core diagnostics will be present

## 📂 Bundle Contents

```
supa_diag/
├── SUMMARY.txt                 # Overview of bundle contents
├── cli_version.txt             # Supabase CLI version
├── projects_list.txt           # Your Supabase projects
├── status.txt                  # Local project status
├── project_ref.txt             # Detected project reference
├── schema_dump.sql             # Full schema DDL
├── database_types.ts           # Generated TypeScript types
├── extract_metadata.sql        # SQL used for metadata extraction
├── metadata.txt                # RLS, triggers, extensions, etc.
├── migrations.tgz              # Compressed migrations folder
└── env_vars_sanitized.txt      # Environment variable names only
```

## 🔍 Example Use Cases

1. **Debugging schema cache errors**
   ```bash
   ./generate_supabase_diagnostics.sh
   # Share supa_diag_bundle.zip with support team
   ```

2. **Documenting database schema**
   ```bash
   ./generate_supabase_diagnostics.sh
   unzip supa_diag_bundle.zip
   cat supa_diag/schema_dump.sql
   ```

3. **Reviewing RLS policies**
   ```bash
   ./generate_supabase_diagnostics.sh
   unzip supa_diag_bundle.zip
   grep "POLICIES" supa_diag/metadata.txt -A 50
   ```

4. **Type definitions backup**
   ```bash
   ./generate_supabase_diagnostics.sh
   unzip supa_diag_bundle.zip
   cp supa_diag/database_types.ts src/types/
   ```
